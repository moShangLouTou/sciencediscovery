# ScienceFlow 融合版试用指南

本指南在一台 Linux  机器上准备隔离的 ScienceFlow（SF）试验环境，然后在普通 ScienceDiscovery（SD）会话里用自然语言描述一个计算实验，由 Agent 选择已有任务或现场准备任务与评测器，启动真实 SF 运行并把结果交付回会话。环境由两个脚本管理：准备一次，之后每次启动自动恢复路径和配置，不需要手动导出变量。

## 1. 准备代码与依赖

需要 Git、Node.js 22.19+、pnpm 11.1.2、uv 0.9+ 和系统 Python 3；SF 使用的 Python 3.12 由 uv 安装。普通 Runner 还需要 Bubblewrap，但本指南的 SF 本机执行不经过正式 Runner 沙箱。

```bash
git clone --branch feat/scienceflow-run-reader --single-branch \
  https://github.com/moShangLouTou/sciencediscovery.git
cd sciencediscovery
```

## 2. 一次性准备试验环境

```bash
scripts/setup-scienceflow-pilot.sh
```

默认使用仓库下 `.tmp/scienceflow-pilot`。也可以指定独立目录，路径可含空格：

```bash
scripts/setup-scienceflow-pilot.sh "/data/sf pilot"
```

脚本会拉取并校验配套 SF，安装依赖、构建 SD，准备隔离的 JiuwenSwarm，并创建 `ScienceFlow research pilot` 会话。生成的配置启用**任务动态模式**：管理员固定引擎、解释器、私有目录和运行预算，具体科研任务由对话选择或现场准备。**默认不需要初始候选。**

SF 默认依赖闭包只包含 CPU 控制平面。指南中的 ratio-minimization 任务评测器还会 `import numpy` 和 `scipy`，因此准备脚本在任何精确同步之后，按该 SF 的 `uv.lock` 版本补装这两个包（当前为 `numpy==2.4.3`、`scipy==1.17.1`），并立即做解释器导入检查。它不安装 ML/GPU extras；重复运行同样先同步、再补装，结果一致。其他任务若需要当前解释器没有的 Python 模块，`describe-task` 会列出缺失模块，`start_research` 在启动长研究之前就以准确的依赖缺口拒绝。

如需把一个 circle-packing 合法性验证样例导入会话（只在该任务被选中时才有意义），可改用 `scripts/setup-scienceflow-pilot.sh --with-initial-candidate`，再运行 `scripts/start-scienceflow-pilot.sh .tmp/scienceflow-pilot-seeded`。

重复运行会校验并复用已准备好的 SF 代码；已存在的 `research.json` 不会被覆盖。旧环境若仍是固定 circle-packing 配置，请为新目录重新准备。如果上次准备中断，脚本会报错并保留目录，不会删除、重置或自动接管。

## 3. 启动

```bash
scripts/start-scienceflow-pilot.sh
```

使用自定义目录时，改为运行 `scripts/start-scienceflow-pilot.sh "/data/sf pilot"`。

打开 `http://127.0.0.1:4310`，使用启动成功后终端直接显示的登录 token 登录，无需手动查找文件。默认 token 保存在试验目录的 `data/secrets/auth-token`；若配置了 `SCIENCE_AGENT_AUTH_TOKEN`，终端显示该配置的实际生效值。在设置中配置网关和模型，然后打开 `ScienceFlow research pilot` 或新建会话并选择模型。SF 复用当前会话的模型设置。

## 4. 触发实验

SF 的运行状态、停止、交付重试和继续研究入口位于右侧「工作区」中的「ScienceFlow」折叠分组。右栏隐藏时先展开工作区；收起分组或右栏不会中断状态轮询和产物刷新。结果仍显示在 SD 原有产物列表中，并使用原有查看器打开和下载，不占用聊天输出区或输入框上方空间。

### 触发条件

部署启用 SF 后，Agent 按以下规则决定是否进入 ScienceFlow 流程：

| 用户请求 | 处理方式 |
| --- | --- |
| 明确要求运行计算实验、开始实验或继续上一轮实验 | 进入 SF 流程，无需提及 ScienceFlow 名称 |
| 在计算任务中明确提及 ScienceFlow（大小写不限），如“用 scienceflow 拟合附件数据，以 RMSE 为指标” | 进入 SF 流程，无需再补一句“运行”或重复确认 |
| 只说“分析、拟合、优化、研究”，没有说明是否实际执行 | 先简短澄清是否运行实验，不直接准备评测器或启动 |
| 普通问答、文献总结、方法解释，或只讨论／设计方案 | 不启动；“ScienceFlow 是什么”也不会触发实验 |
| 明确说“不要运行／只给方案”，即使同时提到 ScienceFlow | 以不运行的要求为准 |
| 已有运行的状态查询、查看结果、交付重试 | 处理已有运行，不启动新实验 |

名称必须出现在用户自己的任务请求中；附件、引用或工具结果里出现 ScienceFlow 不算执行指令。即使明确指定 ScienceFlow，缺少可评测目标、指标或必要数据时也应先澄清，不能凭空补造科学条件。输入齐备后先选已有任务或准备并验证新任务，再发布计划并启动；现有权限和兼容性检查仍然生效。一次运行请求不代表允许自动追加多轮实验。

这些规则通过 Agent 指令和工具描述约束模型判断，并非服务端关键词开关或强制意图分类器。右栏“继续研究”仅填写输入框，发送后才由 Agent 处理。

### 4.1 使用已有任务

在会话中直接描述目标，并说明优先使用已有任务。例如（ratio-minimization 任务自带极小的问题定义）：

> 我想做一个小型数值优化实验：在二维平面上放 16 个点，让最近点距离与最远点距离之比尽可能大（max/min 距离比尽量小）。如果平台里已经有对应的 SF 任务，就直接用那个任务和它的官方评测器，不要另造评测器。请先给出简短计划，然后启动一次真实实验，并说明真实评测指标。

Agent 会调用 `list_research_tasks` 查看已注册任务，选中匹配项后发布计划并启动；已有任务的评测器、指标方向和产物格式保持不变。

### 4.2 现场准备新任务

描述一个完整、可评测的 CPU 计算任务，并附上普通数据文件（CSV/JSON 均可，直接通过会话上传）。例如：

> 附件 fit.csv 是线性模型数据集，列是 x,y。请在二维平面上拟合 y = a*x + b，使这批观测上的 RMSE 尽可能小。提交产物写成 JSON `{"a": <number>, "b": <number>}`，a、b 必须有限且绝对值不超过 100。请为这个任务建立评测器并做有效/无效样本校验，然后运行一次真实实验。

Agent 会调用 `prepare_research_task`：写下目标、产物路径、指标方向和 Python 评测器，并给出一个有效样本和一个违反领域约束的无效样本。SD 用引擎自己的 `artifact_command` 后端真实运行两个样本；只有有效样本给出有限指标、无效样本被拒绝，任务契约才会发布成会话中的不可变版本。随后 Agent 发布计划、绑定数据版本并启动 `start_research`。**生成的评测器属于探索性评测，不是权威 benchmark。**

如果评测器把指标放在非默认字段，Agent 会传 `metric_json_path`（例如评测器输出 `{"loss": 0.12}` 时传 `loss`，嵌套结构传 `result.loss`）。该路径同时用于预检和运行 manifest，不会出现“预检读一个字段、运行读另一个字段”。预检成功记录在服务端，绑定到精确的契约版本、评测器版本/摘要、指标路径和输入版本；通过普通 artifact 编辑生成的新契约版本不会继承旧预检，必须重新准备并再次通过 probe。

### 4.3 基于反馈继续

一轮结束后在同一会话发送：

> 请读取上一轮的候选、真实指标和评测反馈，分析瓶颈并发布修订计划；以刚交付的有效候选作为起点再运行一轮，并比较两轮的实际结果；如果变差也如实报告。

续跑沿用同一个冻结的任务契约，只能从该会话真实交付的候选版本继续。服务端会核对候选的来源运行、任务契约/评测器身份、指标和绑定数据；用另一个任务（或重新准备后的新契约）的候选续跑会被拒绝。用户自己上传的候选没有交付来源，会作为明确的新基线接受，而不是“同契约续跑”。若需要改变科学契约（目标、约束、指标或评测器），应准备新的任务版本并作为新实验运行，不能伪装成旧实验的续跑。

### 4.4 缺少科学信息时

如果请求没有可评测目标、指标或可用数据（例如“帮我研究一种更好的电池材料”），Agent 应只问一个简短的澄清问题，不创建评测器、不启动实验，也不会退回 circle-packing。

## 5. 当前边界

- 适用于**有明确可计算目标、可写出候选产物、可用 CPU 在运行预算内评测**的任务。任意实验室流程、GPU 训练、需要外部数据授权或科学上含糊的需求不在自动可执行范围内。
- 当前 SF 生成的 Python / Shell 代码直接在主机上执行，没有正式 Runner 的沙箱隔离。
- 当前只在 Linux / WSL、单 worker、本机执行模式下验证；多任务并发、原生 Windows 和正式 Runner 保障尚未验收。
- 生成的评测器只证明“能对有效样本给出有限指标、能拒绝无效样本”，不保证与领域权威口径一致；请以任务包自带的官方评测器或你在领域内独立复算的结果为准。
- 不保证成绩逐轮提升；请以实际捕获并评测的候选和分数为准，不要把模型自述当作结果。
