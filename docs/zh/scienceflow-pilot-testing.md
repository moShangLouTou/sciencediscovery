# ScienceFlow 融合版试用指南

在 ScienceDiscovery（SD）会话中描述计算实验，由 Agent 使用 ScienceFlow（SF）执行，并把结果交付回会话。

## 1. 准备环境

使用 Linux / WSL，预先安装 Git、Node.js 22.19+、pnpm 11.1.2、uv 0.9+ 和 Python 3。

```bash
git clone --branch feat/scienceflow-run-reader --single-branch \
  https://github.com/moShangLouTou/sciencediscovery.git
cd sciencediscovery
scripts/setup-scienceflow-pilot.sh
```

准备脚本会下载配套代码、安装依赖、构建应用并创建试用会话。首次准备需要联网，默认数据目录为 `.tmp/scienceflow-pilot`，无需手动配置环境变量或准备初始候选。

## 2. 启动并配置模型

```bash
scripts/start-scienceflow-pilot.sh
```

打开 <http://127.0.0.1:4310>，使用启动成功后终端显示的登录 token 登录。在设置中配置网关和模型，再打开 `ScienceFlow research pilot` 或新建会话。SF 共享当前会话选择的模型。

如需自定义数据目录，给准备和启动脚本传入同一个目录即可。

## 3. 什么情况下会触发 ScienceFlow

| 用户请求 | 处理方式 |
| --- | --- |
| 明确要求运行计算实验或继续上一轮实验 | 进入 SF 流程，无需提及 ScienceFlow 名称 |
| 在计算任务中明确提及 ScienceFlow（大小写不限） | 进入 SF 流程，无需再补一句“运行”或重复确认 |
| 只说“分析、拟合、优化、研究”，执行意图不明确 | 先询问是否实际运行实验 |
| 普通问答、文献总结、方法解释或只讨论方案 | 不启动；“ScienceFlow 是什么”也不会触发实验 |
| 明确说“不要运行／只给方案”，即使提到 ScienceFlow | 不启动 |
| 查询状态、查看结果或重试交付 | 处理已有运行，不启动新实验 |

缺少可评测目标、指标或必要数据时，Agent 会先澄清。附件、引用中出现 ScienceFlow 不算执行请求。一次运行请求不会自动追加多轮实验；需要多轮探索时，请明确说明允许的范围和停止条件。

触发判断由 Agent 根据这些规则完成；进入流程后仍需通过任务准备和权限检查。

## 4. 开始实验

### 使用已有任务

直接说明目标，并要求优先使用已有任务。例如：

> 请用 ScienceFlow 做一个数值优化实验：在二维平面上放 16 个点，让最远点距离与最近点距离之比尽可能小。优先使用平台已有任务及其评测器；先给出简短计划，再运行一次实验并报告实际指标。

Agent 会查找匹配任务、制定计划并启动实验，沿用该任务的评测规则。

### 准备新任务

说明目标、约束和评测指标，需要数据时直接在会话中上传。例如上传包含 `x,y` 两列的 `fit.csv` 后发送：

> 请用 ScienceFlow 拟合附件 fit.csv 中的数据，模型为 y = a*x + b，以 RMSE 最小为目标。a、b 必须有限且绝对值不超过 100，结果保存为 JSON {"a": 数值, "b": 数值}。请准备评测器、验证有效和无效样本，然后运行一次实验。

没有匹配的已有任务时，Agent 会准备并验证评测器，再制定计划和运行实验。自动生成的评测器属于探索性评测，请自行核对其科学合理性。

### 根据反馈继续

一轮结束后，在同一会话发送：

> 请比较本会话中相同任务的所有实验，读取最佳有效候选及其评测反馈，分析瓶颈并提出具体方法修改；从最佳有效版本继续一轮。说明依据哪些证据、预期观察到什么、如何评价、何时停止和本轮预算，变差也如实报告。

Agent 会把后续轮次记录为结构化实验提案，包含研究问题、证据引用、具体方法修改、候选起点、预期观察、评价方法、停止条件和子预算。同一起点、相同方法且没有新证据的重复提案会被拒绝；确需随机重复测量时，应说明目的、随机性和重复次数。当前去重检查不能识别所有语义改写。

继续实验应保持相同目标和评测规则；需要修改它们时，应作为新实验提出。从旧候选开始新一轮实验，不等同于恢复原 SF 运行的检查点。

## 5. 比较结果与选择下一轮起点

系统会分别保留三种关系，它们可以指向不同实验：

| 界面标签 | 含义 |
| --- | --- |
| 最近运行 | 最近启动的实验，不代表结果最好，也可能失败或没有候选 |
| 最佳有效 | 在同一比较组中，按固定指标方向选出的最佳有效结果 |
| 已选为下一轮起点 | 显式选定的候选，可以有意选择非最优路线 |

只有任务版本、数据、评测器、指标方向和执行环境等身份一致的结果才会放入同一比较组。缺分、无效候选、评测或交付失败不会被当成零分；停止、失败或状态未知的运行不会晋升为最佳有效结果。较差的新结果也不会覆盖旧最佳，已有产物版本仍可查看和下载。

在同一会话中可以直接询问：

> 请比较这个任务的所有实验，分别列出最近运行、最佳有效结果和已选定的下一轮起点，给出指标方向、候选版本及比较依据。不能比较的结果请说明原因；这次只查询，不启动实验。

需要探索另一条路线时，可以明确指定某次实验及选择理由：

> 请把实验 `<operationId>` 交付的有效候选显式选为下一轮起点，理由是它使用了不同的求解方法，值得单独探索。保留原来的最佳有效结果；本次只记录选择，不启动实验。

把 `<operationId>` 换成实际实验编号。Agent 通过结果查询和选择工具完成操作，无需手工改文件。后续启动会使用选定的精确产物版本；要改用另一版本，应先更新选择，避免起点与已记录决定冲突。

较旧记录如果缺少可信的任务、评测器或执行环境身份，会继续显示，但不参与排名。当前指标是用于迭代选择的验证指标，不是独立最终评价；小幅数值变化不代表显著改善，也不保证每轮都能提升。

## 6. 总预算与有界多轮研究

新建试用环境默认对每条研究线设置最多 **6 次子运行、5,400 秒总墙钟额度及对应截止时间**，单次默认上限为 900 秒。研究线按同一会话中的冻结比较组关联；这些是上限，不是必须跑满的轮数或时长。

例如，要授权有限的多轮探索，可以发送：

> 请在当前任务和评测规则下开展最多三轮实验，每轮先解释证据、具体方法修改、起点和子预算。每轮结束后比较所有有效结果，再决定继续、换方法或结束。没有新的可验证思路、达到计划中的停止条件或预算不足时就结束，不要为了凑轮数重复实验。

用户要求的轮数和科学停止条件由 Agent 按提案执行；部署配置的次数、资源预留和截止时间由服务强制检查。服务每条研究线最多允许一个活动子运行，启动前预留额度，结束后结算；准备耗时较长时，会收紧剩余运行预算，无法容纳有效实验时拒绝启动。

右侧面板会显示已运行次数、配置上限、剩余墙钟额度，以及因实际用量不可观测而按预留额度计入的结算。任务准备与评测器探测会留有用量记录，Agent 决策的可观测模型用量也会关联记录。无法观测的用量明确标为未知；token 当前仅作统计，**不提供研究总 token 硬上限**。需要细查时，可让 Agent 查询研究线预算、准备记录和已知／未知用量，不要只把 SF worker 的 token 当成全部成本。

已有试用目录的 `research.json` 会被准备脚本保留，不会自动新增或覆盖预算。默认位置为 `.tmp/scienceflow-pilot/research.json`；自定义目录时位于对应目录。旧配置没有 `research.parentBudget` 时，面板会显示未配置次数上限。需要启用相同预算时，可在该配置的 `research` 对象中加入：

```json
{
  "parentBudget": {
    "maxChildRuns": 6,
    "totalAllowanceSec": 5400
  }
}
```

由环境维护者在下次重新启动时加载配置。已有研究线冻结的预算不会因修改配置而重置；重新打开页面或重启服务也不会清空已用预算。

## 7. 查看、停止和下载

右侧「工作区」中的「ScienceFlow」分组显示运行状态、最新指标和交付情况，并提供停止、交付重试和继续研究入口。收起右栏不会中断实验或状态更新。

结果会进入 SD 原有产物列表，可以打开查看和下载。较差的新结果旁会显示仍然保留的最佳有效指标；需要回到更好的起点时，可使用「从最佳有效结果继续」。

「继续研究」和「从最佳有效结果继续」都只会先填写输入框，检查并发送后才进入下一轮流程。如果已有不同的显式起点选择，请在请求中说明需要先更改选择。

点击停止后，先区分「已请求停止」与引擎确认停止；尚未确认时不能认为子进程已结束。同一次对话运行中的停止会阻止后续子运行，恢复研究需要之后的新对话请求明确提出，且仍受原研究线预算约束。

服务重启后会核对已有运行和交付记录，不会自动重新启动实验。交付失败时可重试交付，这只重新发布已有结果，不重新做实验。

## 8. Evolve 与 Idea Tree 的当前状态

- 当前交付的可用闭环是 SD → SF → 结果比较 → 有界续跑。
- Evolve 只有条件核对入口。Agent 可以检查候选格式及缺口，但当前会明确报告执行不支持，不会自动启动搜索。候选与评价器的隔离、评测数据边界、胜者回到原任务评价路径复核，以及父级预算和停止联动均未完成，不能把适配检查当成已跑通优化试点。
- Idea Tree 未接入这条实验链，不会默认先生成多路线，也没有将节点判断回写为实验事实。现有模型评分不能与真实实验指标混算。
- 尚未通过受控真实对照证明融合后的科研成绩提升；当前功能用于保留最佳证据、解释下一轮选择和约束运行成本。

## 9. 适用范围

- 适合目标、约束和评测指标明确的 CPU 计算实验；实验室操作、GPU 训练等不在本次试用范围内。
- 当前 SF 生成的代码直接在本机执行，尚未纳入正式 Runner 沙箱，请在专用试用环境中运行。
- 当前试用面向 Linux / WSL 运行，其他平台及并发运行尚未验收。
